User
Make a functional order tracking module within the web application by the end of the two-week sprint, enabling 100% of authenticated customers to enter an order ID, view real-time fulfillment status updates(e.g. Processing, Shipped, Delivered), and demonstrate all tracking states during the sprint review

User Story 1 (Status Visibility):
As a registered customer,
I want to see the current fulfillment status of my recent purchases on my account dashboard,
so that I know whether my order is being processed, packaged, or shipped.
User Story 2 (Carrier Tracking Link):
As a customer waiting for delivery,
I want to access a tracking link and shipment number on my order details page,
so that I can track the delivery vehicle's transit progress directly via the third-party courier.
User Story 3 (Internal Status Updates):
As an order fulfillment specialist,
I want the system to automatically update the tracking status when a package barcode is scanned at dispatch,
so that buyers receive immediate, accurate tracking details without requiring manual administrative entry.

Developers:

4)
The Daily Scrum is a 15-minute timeboxed event held every business day at the same time and place. Team members synchronize their efforts and inspect progress toward the Sprint Goal by answering three core questions:
What did you complete yesterday?
Share specific tasks finished since the last meeting that advanced the team toward the Sprint Goal (e.g., “Completed the database schema for order tracking states.”).
What do you plan to complete today?
Identify concrete deliverables targeted for the day to keep work aligned with the sprint backlog (e.g., “Will integrate the carrier status API and link it to the frontend component.”).
What roadblocks or impediments are affecting your progress?
Highlight blockers or technical dependencies preventing progress toward the Sprint Goal (e.g., “Waiting on carrier sandbox API keys to complete integration testing”), which the Scrum Master then tracks and resolves outside the meeting.
